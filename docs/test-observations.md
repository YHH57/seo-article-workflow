# 流程测试观察与归类

这些是设计来源，不是每篇文章必须复现的内容。

| 观察 | 归类 | 新 Skill 中的处理 |
|---|---|---|
| 从页面只提出少数技术子问题，遗漏读者的总体任务 | 问题生成的执行方式需改善 | 情境、问题、查询分开；覆盖总体任务，数量由真实差异决定 |
| 读者情境只有一种，用户难选择 | 规划缺口 | 在有实质差别时展开情境，保留编辑假设性质 |
| 问题池尚未展开成文章候选就深入某项技术资料 | 阶段顺序问题 | 候选比较前只查证据可行性，深入研究服务已选方向 |
| 候选只呈现编号、术语和搜索条数 | 交付表达问题 | 用读者问题、具体内容、收获和范围比较，数据作依据 |
| 聚合结果、缓存或不同地区数据容易被误说成当前 Google SERP | 数据真实性问题 | 保存查询条件和样本范围，区分复用、部分适用及缺口 |
| 证据要求使正文反复要求补资料 | 执行偏差与知识使用边界不清 | 区分稳定知识、条件推理和具体待证主张；保留解释而不让边界提示主导全文 |
| 作者身份与语气不明确 | 可复用配置需要 | 作者配置独立且不冒充真实履历，可按领域和读者调整 |
| 结论成为章节压缩或阅读收益总结 | 原有综合要求执行不足 | 回应主旨，选择有解释力的关系，段数不固定；具体判断随类型变化 |
| 对话纠偏句持续堆入提示词 | 规则维护问题 | 清理仅为解释误会的文字，保留实际改变写作决策的要求 |
| 每次审阅都追加可选改动，测试不断延长 | 收尾策略需明确 | 固定本轮范围，修实质问题后交付；偏好另记，后续新输入再决定 |
| 一篇文章的修法可能被误写为所有文章规则 | 过拟合风险 | 行业内容只改案例，通用缺口另评估，并用其他主题测试 |

## 已知边界

原始试验主要是单篇英文外部文章。没有据此验证所有语言、所有行业、批量产能、所有发布平台、实时研究供应商或 HTML 兼容性。新 Skill 的有限测试见 validation.md；正文质量仍需实际用户审阅。
