# 验证记录

日期：2026-11-09。版本：0.1.0。下面是实际执行范围，不是跨行业效果承诺。

## 结构与代码

- skill-creator 的 quick_validate.py：通过命名、frontmatter 与脚手架检查。
- 标准库 unittest：6 项通过，覆盖未知指标不能填零、真实零可保存、市场不匹配不能当匹配复用、修改后的稿件哈希失效、独立 URL 与链接次数的区别、摘要不能声明全文核实、未知来源 ID 和批准状态声明。
- 本地引用、JSON 与 UI 元数据检查：执行于完整文件集，不依赖本机路径或付费服务。
- 检查器只核对声明和文件；不能验证声明背后的实际工具调用、用户同意真实性、来源准确性或排名效果。

## 独立离线行为检查

用三个独立子代理读取 Skill 及最小输入，没有提供预期答案、旧稿或本轮诊断结论。原始输入均为合成资料，保存在 tests/behavior-inputs，真实输入和首次输出哈希见 behavior-checks.json。

| 场景 | 观察到的行为 | 不能据此声称什么 |
|---|---|---|
| 手动咖啡器具页面理解 | 区分页面内容、厂家比较声明、未知和多种读者情境，停在指定阶段 | 没有验证真实产品或需求 |
| 家庭日历软件意图规划 | 美国/英国资料范围分开；未知指标仍 null；完整查询、条件与成本缺口作为计划列出，没有执行 | 没有取得真实美国 Google 结果，也不能认定选题胜出 |
| 非问句标题的咖啡文章结论 | 一个自然段归纳配方条件、调整与记录，没有固定两段或设备选型模板 | 一次短段落不证明长文质量、所有风格或通用提示词效果 |

研究案例的输出将背景材料的复用明确限定为合成记录及元数据；实际使用时，仍需把本轮目标查询的完成状态与背景复用记录分开。此检查没有执行真实查询或采购数据。

## 尚未覆盖

- 新主题的真实检索、意图选择、证据研究到长文交付的完整闭环。
- 多平台实际发布、实时付费供应商、批量内容效果与 HTML 渲染兼容性。
- 作者配置的长期效果、用户最终接受、技术专家复核、搜索排名、收录或 AI 引用。

本轮设备文章只是设计来源和一次持续修改试验；多项输入同时变化，不作单变量因果推断。不分发其旧稿作为成功范本。后续优先用不同主题和文章类型检验可迁移性，避免继续对同一结尾反复优化。
