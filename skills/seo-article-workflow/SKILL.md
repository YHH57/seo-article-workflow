# SEO 文章全流程

面向读者完成有用的文章，同时保留足够记录，让后续修改知道依据、范围和当前版本。适用于不同领域与文章类型；产品适配、机制解释、方法、比较、案例不是同一种结构。

## 恢复任务

确认本轮对象、当前阶段、已有决定与交付范围。用户要审阅就只读，要执行明确的修改就执行；指定逐阶段测试时只完成当前阶段，完整成稿请求则连续完成已授权范围。沿用宿主及用户的批准规则，不额外设置每阶段固定批准门槛。

读取当前稿、brief、研究记录和作者配置中与本阶段相关的部分。优先续作，不因换工具、语气或文件格式重启选题。已批准输入直接使用；用户要求暂不预设关键词、标题或类型时，保持这些字段未定。

区分 `external_article` 与 `owned_blog`。平台、市场或链接属性未知就记录未知；历史研究市场不自动成为发布市场。产品 URL 不自动代表零售电商。

## 工作主线

1. **理解业务与页面。** 确认提供什么、面向谁、页面能承接什么。区分实际读到的事实、厂家自述、推断、冲突和未知。
2. **明确读者处境。** 从读者想理解、决定或完成的事提出不同情境；在情境中展开问题池，再形成可能的搜索表达。三者分开记录，编辑推导不等于已验证意图。
3. **展开文章候选。** 将相关问题组织成不同文章任务，比较读者收获、范围、目标页关系和证据可行性。数量取决于实际差异，不把少数原始问题当作全部选题。
4. **验证意图并选择方向。** 先展示查询方案、复用项和成本；用代表性查询及相关正文判断内容需要。解释保留、合并、调整或放弃的依据。实质选择尚未解决时不宣称已经确定。
5. **研究内容并准备大纲。** 方向稳定后补充真正需要的事实与解释。记录作者配置、关键词和链接计划；大纲写清实际准备解释的内容与关系，而不止写“解释关系、请对方确认”。
6. **生成与编辑。** 按大纲写完整初稿；先解决事实与核心解释，再按需要做一次表达编辑。保留首次输出、重要版本及实际修改理由。
7. **诊断与收尾。** 审阅当前修订版，修有文本依据的实质问题，复核受影响内容。不为追求唯一最佳措辞无限重写。按用户范围交付正文或继续格式化。

这是依赖关系，不是每次必须全部重跑的清单。单段修改只读取相关上下文；改变主题、读者或主要论点才重审相应上游决定。

## 核心边界

- 用户提供、编辑推导、工具发现和观察到的查询分开记录。未知指标为 `null`；确实返回的 0 如实保存。
- 聚合搜索样本不叫单次 Google 前十；标准摘要、资料目录、网页标题不等于核对全文。
- 可用把握充分的基础知识与条件明确的推理解释内容。数字、易变信息、冷门或不确定主张、法规、兼容及性能结论需要相应依据。来源支持内容，不要求每句话都变成索取证明或“咨询厂家”。
- 作者配置是写作视角，不是真实履历；假设、估算、厂家声明、测试结果保持各自性质。
- 旧文章用于后续编辑对照，不代替当前研究；本篇例子、两段结论或固定句式不升级为通用模板。
- 搜索、付费研究、发布及发送遵循当前工具契约与授权。能力不可用时记录缺口，不宣称执行成功。
- 当前稿及审阅记录绑定版本。编辑完成、用户接受、平台发布、收录和流量分别记录。

## 配置与交付

[run.template.json](assets/run.template.json) 保存当前状态；其他模板按需要使用，不为小任务创建全套空文件。

[project-editorial-profile.json](assets/project-editorial-profile.json) 收录本项目的关键词、引用、FAQ、博客链接数量及 HTML 偏好。采用时记录配置名称，用户与平台要求可覆盖。它们不是 SEO 硬性规则，不自动推广到其他项目。

Humanizer、seo-content 是可选组件，使用前读取实际 Skill。没有时按本包完成工作并记录方法；不自动安装，不连续运行多套语言清理器，评分不代替文本判断。

交付可读结果、重要变化、验证范围和剩余限制。流程测试时按 [records-testing.md](references/records-testing.md) 展示输入、工具、查询、决定与产物；内部记录不进入发布稿。

可运行 `python3 scripts/validate_run.py --run <任务目录>/run.json` 核对状态、快照、来源读取范围和链接数量声明。它不执行研究，不证明文风、事实或 SEO 效果。
