# 格式、平台与批量交付

## 只生成请求的产物

默认文章以 Markdown 交付。用户只要大纲或正文时不自动生成 HTML、图片或发布包；已有文章只改格式时不重写内容。图片和其他媒体按其单独授权与工具规则处理。

HTML 若在范围内，从同一经审阅正文派生，不独立再写一篇。标准模式采用浅灰背景、白色阅读页、深蓝标题；其他模式按当前设计。平台模板需要覆盖时记录具体调整，不静默替换已选样式。

保证语义标题、舒适阅读宽度与段落间距、表格在小屏可用。标准模式沿用普通段落引言、不加重复摘要框；FAQ 问题采用 H3 并加粗、答案另起 A: 段落；References 按配置分组编号和分行展示完整 URL。其他模式按各自设定，避免渲染时重新套上标准模式。真实渲染后检查桌面和手机，不以 HTML 文件存在代替视觉核对。

核对 Markdown/HTML 的标题、正文、数据、链接、锚文本、FAQ 与来源一致性。解析器检查只能覆盖可确定的结构和文本项，人工复读负责含义；验证通过不等于平台接受。

## 平台适配与发布交接

平台确定后，核查当前官方编辑、原创、署名、引用与链接限制；记录证据和日期。检查平台实际支持的格式，不假定保留 CSS、rel 或 canonical。平台未知则交付通用稿并列未知，不写“已符合平台规范”。

署名、专业资历、发布日期、披露、canonical 与结构化数据使用真实提供或确认的内容。交付本地文件不包含代发、投稿、邮件发送或上线授权。执行用户已明确授权的发布时，按宿主规则与工具合同完成并验证实际页面；发布、收录、排名各自记录。

## 版本与验收

一个当前正文来源，发布格式由它导出。交付主文件、必要的来源/链接记录、简明 QA、实际修改与未验证项；不把运行日志或内部证据 ID 放进发布正文。

完成点由请求决定：可读的大纲、可审阅的文章或可验证的发布结果。候选规则、作者配置或整篇稿件未通过时保留状态，不因交付就自动批准。

## 多篇与排期

用户明确要求批量时，建立共享业务和适用研究记录，每篇有自己的读者任务、brief、大纲、正文与审阅状态。复用事实不等于复制相同文章结构或案例；不同查询、市场或时期的数据不互换。

按读者任务去重候选，覆盖差异有意义的角度，不为凑类型而生成无证据的案例、ROI 或数据文章。一次产生的候选数量不是固定配额。

排期按真实账号权限、额度、内容产能和编辑规则制定；不存在由本 Skill 保证的“安全发布间隔”。编辑提案、待审核稿和已刊发分别记录，不以同日堆发弥补延期。
