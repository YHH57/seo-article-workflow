# 可选输出格式

## 在大纲阶段展示

向用户用普通语言说明本篇将如何呈现：开头、正文组织、FAQ、结尾、引用，以及交付格式。作者语气来自作者配置，文章内容来自已选方向；选择输出格式不重启选题，也不替换作者配置。

有已确认格式时直接沿用并显示名称，不反复要求选择。未指定时，给出以下简短选择说明，并根据文章需要推荐一种：

- **标准模式**：采用下面的固定骨架，以及配置中的关键词、FAQ、引用、链接和可选 HTML 约定。
- **按内容安排**：按读者、文章任务和平台组织结构，不自动套用标准模式的模块、数量或视觉样式。

用户指定其他模板时按其模板执行，记录为 `custom`。尚无用户选择，也没有已确认配置时，不将推荐冒称已选标准模式；连续完稿请求可以按内容安排并说明采用方式，逐阶段请求则随大纲交付推荐和选择入口，按用户原定节奏继续。格式选项不额外增加统一审批门槛。

## 标准模式如何生效

用户说“标准模式”“按标准格式输出”即采用该模式。唯一配置来源是 [project-editorial-profile.json](../assets/project-editorial-profile.json)，保留既有文件名和 ID 以兼容旧记录。开始按此模式准备大纲时读取配置，后续正文、审阅和格式交付沿用，不自行更换格式。

固定骨架是：

1. 一个 H1。
2. 简短普通段落引言，不另设 Introduction 标题或重复摘要框；相关已核实量化信息有用时自然使用，否则定性表达。
3. 按文章任务组织的 H2，必要时用 H3；章节数量、标题、示例和语气不由模式固定。
4. 有价值时设置 H2 `Frequently Asked Questions`，默认 3 题，可为 2–4 题；只有一题有价值时并入正文，没有需要时省略。问题采用 `### **Q1: 问题**`，答案另起段落，以 `A:` 开头。
5. H2 `Conclusion`，位于 FAQ 之后（如有）、参考资料之前，是最后一个正文部分；段落和句数不固定。
6. 有实际资料时设置 H2 `References`，按需保留 H3 `Sources`、`Related Examples`、`Further Reading`，依此次序排列。每条为连续编号的加粗标题、完整可点击 URL、`Note:`；跨分组续号，正文不用数字角标或脚注。没有内容的分组不保留空壳，也不编造来源。

以上可省略条件是标准模式的一部分，不是任意改版。标准模式的关键词为 1 个主词、3–5 个辅助表达，不设密度；同行产品页与博客仅作内部研究。自有博客按配置安排正文 2 处、Related Examples 2–4 条相关站内链接；外部文章仍按单篇链接计划，不能套用博客配额。缺少相关页面时报告缺口，不凑数。

只有交付范围包含 HTML 时才采用浅灰页面背景、白色阅读页、深蓝标题等视觉配置。选择标准模式本身不请求 HTML、图片或发布。

用户或已核实的平台要求与某项格式冲突时，记录具体覆盖项和原因，交付时说明“标准模式，以下项目调整……”，不静默偏离，也不以选中模式为由忽略明确要求。实际不能满足的配置项保留缺口，不能声称全部符合。

## 记录与复核

在 run 和结构化大纲的 `output_format` 中保持一致：`mode` 为 `standard`、`adaptive`、`custom` 或尚未确定的 `null`；`profile_id` 为采用的配置 ID；`selection_basis` 记用户选择、沿用已确认配置或本次默认安排的依据；`overrides` 记具体字段、变更值和原因。

标准模式沿用现有 `editorial_profile_file` / `editorial_profile_ref` 指向本次使用的配置快照，便于后续恢复；其他模式没有配置时保持空值。对历史任务不追溯改写其已用配置。

审阅时按采用的配置逐项核对格式、模块顺序、FAQ 条件、引用及链接计划；Markdown 和 HTML 如同时交付，内容和模式保持一致。现有 run 检查器不自动证明标准模式格式合规，仍需实际检查输出。
